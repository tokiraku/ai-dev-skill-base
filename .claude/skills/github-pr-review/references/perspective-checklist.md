# PRレビュー観点別チェックリスト（3エージェント用）

`github-pr-review` スキルの Step 2 で並列起動する3エージェントに、それぞれ該当セクションをプロンプトへ含める。

各エージェントは以下の優先度基準で指摘を出す。

| 優先度 | 基準 | 対応期限の目安 |
|--------|------|----------------|
| 🔴 **必須修正** | バグ、脆弱性、CI失敗、データ破損/本番障害リスク、仕様回帰 | マージ前に必ず対応 |
| 🟡 **推奨** | 保守性・可読性低下、将来バグ化しやすい実装、テスト不足 | 次の修正タイミングまでに対応 |
| 🔵 **提案** | リファクタリング案、パフォーマンス改善、PR分割案 | 余裕があれば対応 |

---

## 1. セキュリティ・信頼性レビューエージェント

**入力として渡すもの**: PR差分本文、変更ファイル一覧

**最優先チェック（シークレット・APIキー混入）**:

- [ ] APIキー・アクセストークン・シークレットキーの文字列リテラル（`sk-...`, `ghp_...`, `AKIA...` 等のプレフィックスパターン含む）
- [ ] パスワード・認証情報の直接記述（`password = "..."`, `secret = "..."` 等）
- [ ] 接続文字列に認証情報が含まれるもの（`postgresql://user:pass@host/db` 等）
- [ ] `.env` / `credentials.*` / `*.pem` / `*.key` 等のシークレットファイル自体の差分への混入
- [ ] `.gitignore` に `.env` 等のシークレットファイルが除外されているか

**通常チェック**:

- [ ] 入力検証がシステム境界（APIエンドポイント・ユーザー入力）で行われているか
- [ ] 認可チェックがサーバーサイドで行われているか（クライアント側のみの権限チェックは🔴）
- [ ] 例外処理でエラーを握りつぶしていないか（空catch）
- [ ] SQLインジェクション・XSS・コマンドインジェクション・パストラバーサル対策が適切か
- [ ] データ整合性（トランザクション境界、部分更新時の不整合）に問題がないか
- [ ] スタックトレース・内部パス等の情報漏洩がレスポンス/ログに含まれていないか

**出力形式**: `PR-xxx` 形式、優先度（🔴/🟡/🔵）、ファイル:行番号付き。シークレット混入を発見した場合は必ず🔴で最上位に報告する。

---

## 2. 回帰・設計レビューエージェント

**入力として渡すもの**: PR差分本文、変更ファイル一覧、既存レビューコメント（あれば）

**チェック項目**:

- [ ] 既存仕様を壊す変更がないか（呼び出し元・API契約への影響）
- [ ] 境界条件（空・null・最大値・並行実行）の考慮漏れがないか
- [ ] 後方互換性が必要な箇所で破壊的変更をしていないか
- [ ] 変更粒度が適切か（1PRに複数の無関係な変更が混在していないか）
- [ ] 複雑度が不必要に上昇していないか（ネスト過多、責務過多な関数）
- [ ] 命名・可読性が規約（`.agents/rules/code-style.md`）に沿っているか
- [ ] `.agents/rules/architecture.md` のレイヤー構成・依存方向（フロント/バック分離、DDDの内側方向依存）に違反していないか

**出力形式**: `PR-xxx` 形式、優先度（🔴/🟡/🔵）、ファイル:行番号付き。

---

## 3. テスト・CI・運用レビューエージェント

**入力として渡すもの**: CI/チェック結果、変更ファイル一覧、PRタイトル・説明文

**チェック項目**:

- [ ] CIチェックが失敗/未実行のまま残っていないか（失敗は🔴）
- [ ] 変更点に対応するテストが追加/更新されているか（`.agents/rules/testing.md` のテストピラミッド準拠）
- [ ] domain層相当の変更にユニットテストがあるか、infrastructure層相当の変更に統合テストがあるか
- [ ] エッジケース（空・null・境界値）のテストが漏れていないか
- [ ] PRタイトル・説明が変更内容を正確に反映しているか
- [ ] PRサイズが大きすぎてレビューしづらくないか（分割余地があれば🔵で提案）
- [ ] 既存の指摘済み論点（レビューコメント）が未解決のまま残っていないか

**出力形式**: `PR-xxx` 形式、優先度（🔴/🟡/🔵）、ファイル:行番号付き。CI失敗を発見した場合は失敗しているチェック名を明記する。
